## Intake rules

When the product-owner delta is provided, record each item under one of these headings:

1. **Newly required** — a requirement that is not already implemented.
2. **Changed requirement** — a deliberate replacement for current behavior or an earlier requirement.
3. **Confirmed current behavior** — existing behavior the product owner explicitly wants retained.
4. **Deferred or rejected** — work intentionally kept out of the current scope.
5. **Open decision** — a material choice that must not be resolved by implementation guesswork.

For every item, preserve:

- the product-owner wording or a faithful concise restatement;
- the affected journey/module;
- whether it changes product behavior, data, architecture, operations, or documentation;
- acceptance evidence, if supplied; and
- conflicts with current implementation.
