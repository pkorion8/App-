# Sim Venture Experience Blueprint

The product must feel like distinct environments, not repeated report pages.

## Shared principles
- Visual hierarchy is structural: icons, accent, typography, spacing, motion and composition must make each area identifiable before reading.
- Every page must answer one clear question and introduce genuinely new information or action.
- Facts, findings, assumptions, decisions, simulated outcomes, recommendations and real outcomes must never look interchangeable.
- Simple Mode shows one primary answer and one next action. Pro Mode exposes evidence, provenance, system state and deeper controls.

## Area identities

### Venture Home — Command Centre
Purpose: Where am I, what changed, and what should I do next?
Visual: overview/status map, progress, one primary next action, recent changes.

### Research — Evidence Desk
Purpose: Is the problem real and what does external evidence say?
Visual: source/evidence motifs, citations, finding strength, unresolved questions.

### Shape — Product Canvas
Purpose: What exact version of the idea are we choosing?
Visual: editable audience/problem/value/MVP blocks, before-vs-after changes.

### Simulator — Flight Deck
Purpose: What could happen when I make venture decisions over time?
Visual: timeline, runway, event stream, decision checkpoints, branch map, speed controls.

### Build — Build Room
Purpose: What should I actually make first?
Visual: roadmap, feature priorities, dependencies, build phases, time/cost ranges.

### Learn — Reality Lab
Purpose: What actually happened and what did it change?
Visual: expected-vs-actual comparisons, assumption changes, lessons and next experiments.

### Investor World — Live Meeting Room
Purpose: Can I defend this venture under realistic investor scrutiny?
Visual: investor presence, voice/text answer controls, transcript, meeting state, evidence challenge panel and possible early termination.

## Investor World behavior
- It is not a fixed pipeline.
- Each answer can continue, trigger a follow-up, trigger an evidence challenge, reduce trust, or end the meeting.
- Bad conduct can end the meeting immediately.
- Very weak/evasive answers should be challenged rather than politely advancing.
- Unsupported traction/revenue/customer claims must be flagged.
- Diligence, committee and negotiation only unlock when the meeting state warrants them.
- Voice input should transcribe into the same evaluated answer path, with text fallback.
- A future animated/video avatar can be added later; the first meaningful distinction is adaptive behavior + voice + meeting presence, not decoration alone.
